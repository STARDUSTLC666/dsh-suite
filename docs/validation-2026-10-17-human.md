# DSH alpha.5 · 逐插件操作复查

宿主为公开 npm `@deepseek-ai/dsh@0.2.1-alpha.5`，官方标签 `dsh-v0.2.1-alpha.5`，提交 `1517a4dbca0a2789ff1d41ba439600f8547d23fa`。使用 Windows Node 24、独立 DSH profile 与系统 Chrome 无头浏览器；Browser 插件不可用，采用 Playwright。没有切换用户前台窗口。

Suite **0.2.27** 精确同步日历 **0.10.4**、邮件 **0.16.3** 与 RSS **0.6.3**。其他组件保持原版；极简 PTC **0.5.6** 的 SDK 修复已在上一版发布。

## 实际修复

- 日历：关联日程与连接表单标签，点击文字可聚焦输入框；修正英文 Custom CalDAV；首次读取配置完成前暂缓打开连接编辑器，避免快速点击看到空配置。
- 邮件：配置错误使用逗号分隔服务商选择，避免列表被当作长认证字符串脱敏。真实凭据的脱敏规则保持不变，并增加两者组合的回归。
- RSS：窄窗口切换为顶部设置导航，并让长英文和筛选控件适应可用列，避免标题截断或按钮挤成过窄一列。样式只作用于当前包含 RSS 面板的设置窗口。

聊天工具路径使用显式标注的本地合成模型适配器来稳定选择工具，再交给真实 DSH 执行。它证明聊天、工具、审批和渲染的连接，不是远程模型自主选择工具的证据。

七个工作台补查英文导航、按钮和 390px 可用列，保留用户原始中文内容。未配置账号的 Calendar / Email 用例有预期 HTTP 400，不把该业务拒绝当作页面崩溃。

## 启停、回归与发布

在同一已保存会话、同一文档中，关闭 PPT 后 `/dsh-ppt` 从技能菜单消失；重新启用后返回。没有刷新页面来绕过缓存。

组件自动测试、共同加载、公开 npm 文件与 CI 产物摘要、官方 CLI 全新安装分别检查。共同加载仍包含全部 18 个组件及 Suite 的 SDK、调度、工具和技能清单；这不要求连接未配置的外部服务。

## 明确未验收的范围

- 按用户要求，Docker、Slack、钉钉的业务操作暂缓，三个独立包没有改动或重新发布。
- 没有操作原生桌面窗口，没有调用真实远程模型，没有使用真实 CalDAV、邮箱、OAuth、MySQL/PostgreSQL 或 TTS/ASR 账号。
- RSS 本轮不重测真实网站，也不声称无 VPN 连接已验证；视频工作台本轮验证工程操作，不代替最终渲染验收。

自动测试、基础交互、真实账号业务与原生桌面验收是不同证据。
