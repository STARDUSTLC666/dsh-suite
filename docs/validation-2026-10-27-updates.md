# 0.4.0：每个插件的更新入口（2026-10-27）

每个插件在自己的工作台或设置中提供检查、更新记录、稍后、忽略和确认安装入口，不新增总更新页。自动检查默认开启；自动安装默认关闭，明确授权后也只在空闲且没有未保存修改时安装兼容稳定补丁。不自动重启或升级 DSH，不替换本地源码或 Git 安装，不自动开启已停用插件。

Suite 是一个安装包：组件入口先说明整包范围，再进入 Suite 的更新设置。更新整包不额外安装组件，也不为独立安装的插件开启自动更新。旧版本需先通过官方插件管理手动更新一次，才能获得新入口。

## 已验证

- Windows 本地：20 个独立插件的测试全部通过；共享库 30 项、Suite 12 项测试通过。
- 云端：20 个独立包的发布检查通过，公共 registry 元数据、精确依赖及下载 tarball 的 sha512 完整性已核验。共享库另通过 Windows/Linux、Node 22/24 四组检查和 npm OIDC 发布。Computer Use 的原生构建检查运行于 Windows。
- 官方 DSH 0.2.1-rc.3 Web：全新安装 20 个公开 npm 插件，逐个打开九个工作台更新按钮和十一个独立设置项；自动安装均保持关闭，浏览器无脚本错误。
- 代表性真实升级：在隔离 profile 中，通过界面将公开 FFmpeg 0.6.0 更新到 0.6.1，保持启用状态；检查、看更新记录、取消确认均不安装。自动安装需单独确认，可以立即关闭，其他包的开关不受影响。
- 恢复：在安装调用边界注入受控失败，官方接口实际移除并恢复 0.6.1；该项证明恢复流程，不等同于真实网络故障。
- 界面：中文、英文、深色主题、390px 窄屏、确认与取消、偏好持久化及未保存保护通过操作检查。

## Suite 边界

官方管理器只列出顶层 Suite 依赖，组件是传递依赖。已以该真实库存形状复现并修复组件入口遗漏：只为实际加载且构建时已标识的组件补充显示，不伪造独立安装目标。组件页面与设置仍显示各自名称和版本；安装与偏好由真实 Suite 记录管理。源码隔离 fixture 和公开组件依赖下的官方宿主分别验收，不能用 fixture 代替 npm 整包安装结果。

## 本轮未覆盖

桌面原生窗口、Electron IPC 和系统更新器未逐项操作；本轮界面验收在 Windows 上的官方 Web 宿主完成。未新测真实 Slack/钉钉账号、AgentMail API Key 或 Docker 引擎，也未发送真实消息或调用付费模型。Computer Use 的早期 GUI 集成检查只操作自有测试窗体；真实第三方应用与长时间自主操作未在本轮验收。
