# Suite 0.2.14: PPT, Calendar and Email

This release pins the three most downloaded independent components in the 2026-09-24 through 2026-09-30 npm snapshot: PPT 0.7.0, Calendar 0.9.4 and Email 0.14.7. The other 15 component pins and both loader patches are unchanged. DingTalk work is deferred.

PPT generated HTML now includes previous/next and page-number navigation, a review panel with issue and outline links, and editable PPTX/project downloads. Draft placeholders remain clearly marked. Collision-resolved filenames are used for sibling download links, preserving the three-file offline format. The deck is editable through existing Agent project tools or PowerPoint/WPS; this release does not introduce an in-browser layout editor.

Email displays effective manually configured servers instead of preset defaults, refreshes the summary after provider changes, and never persists display projections. ImapFlow 2.2.1, Mailparser 3.9.33 and Nodemailer 10.0.13 replace outdated dependencies. Missing IMAP messages, empty searches and missing attachment streams are handled explicitly. Calendar updates Undici to 8.11.2 and preserves CalDAV REPORT method, body and auth through a local HTTP proxy, including response-read cancellation. Proxy use remains optional when the server is reachable directly.

Validation host: official-source DSH 0.2.0-rc.2 (`639ed015397290b3745d163aafe02ffee4aa3f84`), Windows, Node 24.16.0. Plugin tests passed: PPT 103, Calendar 180, Email 304. Independent GitHub CI passed for commits `99c6aadd407f7a923ddf6de1158c71afe38b1945`, `94146e36726571ace9fcedc94a52401574b201aa` and `5e0eed5e95aafba4fa9e8792f36edd90b8fced5b`. Fresh tarball installation passed root imports, Email regressions, the Calendar local proxy tests and new PPT generation with download targets. The three-component consumer production audit reported zero findings.

Visible browser acceptance covers PPT navigation, issue-to-slide links, draft labeling, English controls and 390px width; Calendar local CalDAV agenda, connection testing and saved configuration; Email effective servers, useful local login-failure feedback and auto-save surviving reload while stored passwords remain blank in the editor. The network fixtures and accounts were synthetic. No personal profiles, credentials, calendars or mailboxes were used. Native DSH desktop-window interaction and production email/Google/iCloud service acceptance remain separately unverified in this round.

Suite frozen installation, manifest tests, contracts, official CLI loading and public npm integrity checks are verified separately before completion.
